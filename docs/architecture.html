Data flow

How a filter change on the dashboard becomes updated numbers on screen.

  1. User picks a filter. Four shared refs (period, location, category, status) live in useFilters.js as a singleton, so every view and the filter bar see the same state.
  2. A watcher fires. The view (e.g. Dashboard.vue) watches the four refs and calls getCurrentFilters(), which maps them to warehouse, category, status and month.
  3. API client builds the request. api.js adds only non-all values as query params and sends Axios GETs to http://localhost:8001/api/....
  4. FastAPI filters in memory. Endpoint handlers run apply_filters and filter_by_month (months or Q1-2025-style quarters) over the lists loaded from JSON.
  5. Response is validated and returned. Pydantic response_models shape the JSON; the dashboard summary computes inventory value, low-stock count and pending orders on the fly.
  6. The view renders. Raw data sits in refs, and derived values (totals, chart series) are computed properties that update the UI.

Things worth knowing

  • Frontend calls endpoints the backend does not define. api.js requests /api/tasks (GET, POST, PATCH, DELETE) and /api/purchase-orders (POST, GET), but main.py has no routes for them. All its routes are GET. Task and purchase-order actions will fail until those are added.
  • Read-only data. Because data is loaded from JSON at startup, any write would only live until the server restarts.
  • Hardcoded URL. The API base URL http://localhost:8001 is written into api.js and Reports.vue; there is no Vite proxy or env config.
  • Open CORS. The backend allows any origin, which is fine for a local demo only.
  • Inventory has no time dimension, so the period filter does not apply to inventory.
